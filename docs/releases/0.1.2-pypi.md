# Publish MLX-One 0.1.2

The maintainer authorized version **0.1.2** and its PyPI upload on 10 November
2026. The previous published version is **0.1.1**, verified against PyPI's JSON
API. This handoff includes the ten new native checkpoint workflows and current
documentation. The [release decision](0.1.2.json) tracks approval and publication.

## Build and verify

From the repository root, with build and Twine installed:

```bash
python scripts/release/pypi_readme.py --check
python scripts/release/validate.py
python -m build --outdir dist/pypi-0.1.2
python -m twine check --strict \
  dist/pypi-0.1.2/mlx_one-0.1.2-py3-none-any.whl \
  dist/pypi-0.1.2/mlx_one-0.1.2.tar.gz
```

The prepared wheel and sdist are kept in that dedicated directory, with a
`SHA256SUMS` file. Their exact identities, package audit and isolated installed
checks are recorded in `0.1.2-pypi-validation.json` alongside this guide.
Rebuilding creates different artifacts and requires new hashes and checks.

## Upload the prepared files

Use the PyPI account's configured token or credential store. For an interactive
token prompt in your terminal, run:

```bash
cd dist/pypi-0.1.2
shasum -a 256 -c SHA256SUMS
python -m twine upload --repository pypi --username __token__ \
  mlx_one-0.1.2-py3-none-any.whl \
  mlx_one-0.1.2.tar.gz
```

After successful upload, verify both remote SHA-256 values against `SHA256SUMS`
and install `mlx-one==0.1.2` from PyPI. Then mark publication complete in the
release decision. Push the code branch and merge into `main` so source links and
the GitHub Pages documentation match the published package.

The older restricted-alpha GitHub release workflow uses a different evidence
format. This release uses the current verified model records and the locally
audited artifacts; it does not claim that older workflow performed publication.

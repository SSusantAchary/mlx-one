# MLX-One 0.1.4 — Git and PyPI handoff

The local release checkout is `mlx-one-release-014`, branch `release/v0.1.4`.
Publication is pending. PyPI uses version **0.1.4**; the GitHub tag is **v0.1.4**.
The older development checkouts remain separate.

## Push and merge

Run from this release checkout after reviewing the diff and local validation:

```bash
git status --short
git add -A
git commit -m "Release mlx-one 0.1.4 with serving and chat improvements"
git push -u origin release/v0.1.4
```

Open a pull request from `release/v0.1.4` into `main`, review the hosted checks,
then merge it. GitHub Pages deploys through the **Documentation site** workflow
on `main`; branch pushes and pull requests do not publish the production site.
Repository Settings → Pages must use **GitHub Actions** as the source.

After merge, tag the tested release commit from this same checkout:

```bash
git fetch origin
git tag -a v0.1.4 release/v0.1.4 -m "MLX-One 0.1.4"
git push origin v0.1.4
```

Create the GitHub release using tag `v0.1.4`, title `MLX-One v0.1.4`, and
[the prepared release notes](0.1.4-github.md). Attach the two validated
distribution files from `dist/pypi-0.1.4/` if desired.

## Validate and upload the prepared artifacts

Do not rebuild or upload older files from another `dist` directory. The prepared
directory contains only the versioned wheel and source archive plus checksums.
With build/Twine available in your active environment:

```bash
shasum -a 256 -c dist/pypi-0.1.4/SHA256SUMS
python -m twine check --strict \
  dist/pypi-0.1.4/mlx_one-0.1.4-py3-none-any.whl \
  dist/pypi-0.1.4/mlx_one-0.1.4.tar.gz

python -m twine upload \
  dist/pypi-0.1.4/mlx_one-0.1.4-py3-none-any.whl \
  dist/pypi-0.1.4/mlx_one-0.1.4.tar.gz
```

Use your locally configured PyPI credentials or Twine's token prompt. Keep tokens
out of source files and chat. Publishing PyPI files is a maintainer action; the
manual legacy restricted-alpha release workflow is not this maintenance release's
qualification record.

## Install the published version

After PyPI confirms both files, install into the intended `mlx` environment:

```bash
unset PYTHONPATH
python -m pip install --upgrade "mlx-one[server]==0.1.4"
python -m pip check
mlx-one --version
```

Verify the remote filenames and checksums against `SHA256SUMS`, then update the
publication state in `docs/releases/0.1.4.json` and the homepage/README wording.
Local preparation, merging, tagging, Pages deployment and PyPI publication are
separate events; none is inferred from another.

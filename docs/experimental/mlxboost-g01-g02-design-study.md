# MLX-Boost G01/G02 design study

**DESIGN COMPLETE — NOT IMPLEMENTED / NOT ACTIVATED.** G03 qualification has an independent verdict in [the qualification report](mlxboost-g03-final-qualification.md). Neither design adds a kernel, binding, adapter, registry entry, feature flag or build target. No G01/G02 GPU parity or performance result exists.

The detailed studies are [G01 residual addition plus RMSNorm](mlxboost-g01-design.md) and [G02 activation-only SwiGLU](mlxboost-g02-design.md). They include exact local call graphs, family eligibility, dtype/cast order, proposed interfaces, memory ownership, negative eligibility, standalone/model test matrices, future measurements, packaging dependencies, and ranked recommendations. [The source appendix](mlxboost-g01-g02-source-appendix.md) identifies pinned references and machine-readable mappings.

| Design | Existing baseline and precise boundary | Recommendation for a later assignment | Exclusions and principal risk |
| --- | --- | --- | --- |
| G01 | Materialized residual addition followed by the existing `mx.fast.rms_norm`; return both residual sum and normalized output because both remain live | Conditional research GO for a narrow Llama intra-block boundary; compare eager add+fast norm and compiled two-output graph before proposing native code | Preserve activation-dtype rounding before RMS and normalization cast before weight multiplication. ZMLX's inspected fused operations use different cast points; its Qwen fidelity exclusions remain a HOLD. Gemma3 clipping and `1+w` require a separate contract; hybrid LFM2 state requires separate validation |
| G02 | Existing shared `@mx.compile(shapeless=True)` SiLU(gate)*up; separate projection outputs and unchanged down projection | Research GO to measure the actual compiled launch/memory baseline; conditional later activation-only separate-input Llama study, then LFM2 | Compilation may already remove the proposed overhead. Standard and explicit FP32-precise helpers are different contracts. Qwen remains a fidelity HOLD; Gemma3 uses GELU; GPT-OSS has clipping, alpha and +1 semantics. Projection/MLP fusion is out of scope |

There is no evidence that either proposal accelerates inference. Physical 8/16/24 GiB devices need separate measurements; an 8 GiB allocation budget on this M4 32 GiB host does not establish their performance. A later implementation must pass the unchanged numerical, logits, cache/state, deterministic generation, memory, dispatch and independent wheel gates, with its own operation/math identity and evidence. G03 results do not qualify another operator.

The recommended order is: resolve reference controls and complete G03 evidence; profile the existing compiled/fast graphs; if warranted and separately authorized, prototype one narrow eligible contract; qualify tensor and model behavior independently; retain default-off fallback until a separate product decision. This assignment stops at source analysis and reviewable designs for G01/G02.

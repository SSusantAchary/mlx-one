## Verified Qwen3.5 loading repair

Modified `src/mlx_one/models/vision_language/qwen3_5/weights.py`. Local MLX-LM `models/qwen3_5.py:TextModel.sanitize` folds 1 + weight into attention/final/block norms when converting HF convolution layout [channels, 1, kernel] into MLX [channels, kernel, 1]. Its layers use ordinary nn.RMSNorm. Independent Transformers `models/qwen3_5/modeling_qwen3_5.py:Qwen3_5RMSNorm` and MLX-One use offset norms, multiplying by 1 + weight at forward time. MLX-One previously accepted publisher MLX layout while leaving already folded scale tensors unchanged, applying the offset twice.

The sanitizer now subtracts one from only the affected text block, Q/K and final norm tensors when publisher MLX 3D convolution layout is observed. Gated-delta output norm and vision norms remain unchanged. HF layout and already native 2D tensors preserve their convention; repeated native sanitation is idempotent. Mixed HF/MLX layouts are rejected. This is a tensor-format correction, not a change to recurrent mathematics or attention. CPU mapping regressions passed; local reference offset-norm/L2/GQA/RoPE tests and tiny native inference passed. The before/after Q4 results remain source-bound and the unchanged FP16 gate still fails. No new precision support is advertised.
